# Documentation Standards

This document outlines the requirements and format for all technical documentation within the Hanseatic Strategos project.

## Core Principles
1. **Accuracy**: Documentation must reflect the current state of the codebase.
2. **Clarity**: Use precise technical language while remaining accessible to new developers.
3. **Consistency**: Follow the established templates for components, systems, and screens.
4. **Discoverability**: All documents must be linked from the `MASTER_INDEX.md`.

## File Structure & Naming
- Use **SCREAMING_SNAKE_CASE** for folder names (e.g., `UI_ATOMS`, `LAYOUT_SYSTEM`).
- Use **SCREAMING_SNAKE_CASE** or **Descriptive_Snake_Case** for filenames (e.g., `PROJECT_GOALS.md`, `UTILITY_HOOKS.md`).
- Group files by domain (e.g., `05_SIMULATION`, `20_COMPONENTS`).

## Component Documentation Template
Every UI component documentation must include:
- **Header**: Name of the component and file path.
- **Description**: High-level purpose.
- **Props**: List of properties with types and default values.
- **State & Logic**: Explanation of internal state and key functions.
- **Styling Logic (Tailwind)**: Key classes and conditional styling patterns.

## Code Block Standards
- Always specify the language for syntax highlighting.
- Use realistic examples that reflect the actual project usage.

## Forensic Auditing Process
Documentation generated by agents should:
1. Scan the source files using `read_file` or `glob`.
2. Extract actual props and types from TypeScript definitions.
3. Identify Tailwind patterns used in the `className` attributes.
4. Document side effects (e.g., `useEffect`, event listeners).
